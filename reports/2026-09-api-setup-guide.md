## 1. 공공데이터포털 가입

1. https://www.data.go.kr 접속 → 오른쪽 위 **회원가입** (개인 회원, 간편인증 가능)
2. 로그인

---

## 2. API 활용신청 (5건)

각 링크를 열고 → **[활용신청]** → 아래 내용 입력 → **[활용신청]** 완료.

### 공통 입력값

- **활용 목적:** `웹 사이트 개발`
- **상세 기능 설명** (공통 문장, 그대로 복사):

> 비영리 육아 정보 웹사이트 BeInside(https://beinside.kr)에서 사용합니다. 출산 후 첫 12개월 아기를 돌보는 보호자에게 공식 출처와 확인 날짜를 붙인 정보를 제공합니다. 광고와 상품 판매는 없습니다. 이 API는 운영자가 월 1회 정도 호출해 공식 정보의 변경 여부를 확인하고, 공식 누리집 링크와 기준일을 정적 페이지에 반영하는 데 씁니다. 이용자의 개인정보나 위치정보는 받지 않습니다.

- **라이선스 표시:** 이용허락범위에 동의 체크
- 화면에 "비영리/영리" 선택이 있으면 **비영리**

### 신청 목록 (공통 문장 뒤에 한 줄씩 덧붙이기)

| # | API | 신청 링크 | 덧붙일 한 줄 |
|---|---|---|---|
| 1 | 중앙부처복지서비스 (한국사회보장정보원) | https://www.data.go.kr/data/15090532/openapi.do | 부모급여·첫만남이용권·아동수당 등 영유아 대상 중앙부처 제도의 공식 상세 링크와 신청 방법을 최신으로 유지합니다. |
| 2 | 공공서비스(혜택) 정보 (행정안전부) | https://www.data.go.kr/data/15113968/openapi.do | 출산·영유아 관련 공공서비스의 수정일을 확인해 제도 변경을 반영하고 정부24 신청 링크를 안내합니다. |
| 3 | 예방접종 대상감염병 정보 (질병관리청) | https://www.data.go.kr/data/15009302/openapi.do | 영유아 표준 예방접종 시기에 관한 안내 문장이 질병관리청 공식 정보와 일치하는지 확인합니다. |
| 4 | 식품 회수·판매중지 정보 (식약처) | https://www.data.go.kr/data/15074318/openapi.do | 분유·이유식 회수 정보를 운영자가 점검해, 관련 카드에 공식 회수 목록 확인 안내를 보강합니다. |
| 5 | 공산품 리콜 정보 (공정위) | https://www.data.go.kr/data/15059073/openapi.do | 영유아 수면·이동 용품 리콜을 운영자가 점검해, 관련 카드에 소비자24 확인 안내를 보강합니다. |

> 링크가 열리지 않거나 이름이 다르면, data.go.kr 검색창에 API 이름을 넣어 찾으면 됩니다.
> 신청 페이지에 적힌 **이용허락범위**(예: 저작자표시, 변경금지 등)를 캡처 대신 **글로 적어서** 알려 주시면 좋습니다.

## 3. 인증키 확인

1. data.go.kr → 오른쪽 위 **마이페이지** → **데이터 활용** → **Open API** → **활용신청 현황**
2. 각 API 상태가 **승인**인지 확인 (자동승인이면 바로, 심의면 기다림)
3. 아무 API나 눌러 **일반 인증키** 확인
   - **Decoding** 키를 쓰세요 (Encoding 키는 이미 변환된 값이라 이중 인코딩 오류가 날 수 있음)
   - 키는 계정당 하나라 5개 API 모두 같은 키입니다
4. 신청 직후 키가 바로 안 먹는 경우가 많습니다(보통 1~2시간 뒤 동작).

## 4. 국가건강정보포털 (신청 완료분)

1. https://health.kdca.go.kr → 로그인 → OpenAPI 신청 화면
2. 오른쪽 위 빨간 **[Open API 가이드 다운로드]** → PDF 저장
3. 이 PDF를 저장소 `reports/sources/` 폴더에 올려 주세요 (GitHub 웹에서 Add file → Upload files 가능)
   - PDF에 개인 인증키가 적혀 있으면 올리지 말고 알려 주세요
4. 승인되면 목록의 **URL 칸**에 콘텐츠별 주소가 생깁니다. 그 주소에 키가 들어 있으면 공유하지 말고, 키만 5번처럼 환경 변수로 넣어 주세요.

## 5. 인증키를 클라우드 환경 변수로 넣기

1. 이 Claude 세션 화면 위쪽 제목 옆 **환경(클라우드) 메뉴** → **Edit**
2. **Environment variables**에 아래처럼 추가 (값은 실제 키)

```
DATA_GO_KR_KEY=여기에_data.go.kr_Decoding_키
KDCA_API_KEY=여기에_국가건강정보포털_키(발급된 경우)
```

3. 저장 후 **새 세션**을 시작하거나 이 세션에 알려 주세요 (환경 변수는 세션 시작 때 적용될 수 있습니다).

> 저장소의 `.gitignore`에 `.env`를 넣어 두었습니다. 로컬 PC에서 작업할 때도 키는 `.env` 파일에만 두세요.

## 6. 네트워크 허용 도메인 추가

같은 Edit 화면 → **Network access** → 허용 도메인(Allowed domains)에 추가:

```
apis.data.go.kr
health.kdca.go.kr
```

출처 원문 대조까지 하려면 함께 추가 (선택):

```
*.go.kr
*.or.kr
www.nhs.uk
www.nice.org.uk
www.healthychildren.org
```

> 접근 수준 설명: https://code.claude.com/docs/en/claude-code-on-the-web

## 7. 준비되면 알려 주세요

"API 준비됐어"라고 보내 주시면 제가:

1. 키가 환경 변수로 들어왔는지(값은 보지 않고 존재만) 확인
2. 각 API를 한 번씩 호출해 응답 형식·수정일 필드 확인
3. `scripts/`에 월 1회 점검 스크립트 작성 (결과: 바뀐 제도·리콜·원문 목록 보고서, 사이트에는 링크와 기준일만 반영)
4. 파일럿 카드 3장의 국가건강정보포털 출처 문장을 원문과 대조

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 승인 직후라 아직 반영 안 됨 → 1~2시간 뒤 다시 |
| `SERVICE ERROR` / 인코딩 오류 | Encoding 키 대신 **Decoding** 키 사용 |
| 신청 버튼이 없음 | 로그인 확인, 또는 "파일데이터"가 아닌 "오픈API" 탭인지 확인 |
| 심의 대기 | 심의 대상 API는 최대 2주. 나머지부터 진행 |
