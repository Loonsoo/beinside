# BeInside 공공 API 후보 조사 (2026-09)

- 작성: 2026-09-28 · 조사 방식: WebSearch만 사용
- **이 환경에서는 data.go.kr, e-gen.or.kr, health.kdca.go.kr 등 원문 페이지를 열 수 없었다.** 아래 내용은 모두 **검색으로만 확인**한 것이다. 특히 **갱신 주기, 이용허락범위(공공누리 유형), 호출 한도** 가운데 "확인 필요"라고 적은 항목은 신청 화면에서 운영자가 직접 확인해야 한다.
- 전제(`CLAUDE.md`, `scripts/build-cards.mjs`, `vercel.json` 기준): 정적 SPA이고 서버는 없다. `buildCommand`는 비어 있다. 빌드는 로컬에서 돌리고 생성물을 커밋한다. 1인 운영(주 5~10시간). 새 기능은 억제한다(예외: 카드 렌더러, 카드 검색·상황 칩, 카드별 정적 페이지). 약 용량·제품명·진단 추정은 쓰지 않는다. 광고·커머스는 없다.

## 1. 요약

### 판단의 틀 (한 문단)

BeInside에서 공공 API가 가장 크게 기여하는 곳은 **사용자 화면이 아니라 운영자의 유지 작업**이다. 카드마다 공식 출처 2개와 확인 날짜를 달고 매년 다시 확인해야 한다(재포지셔닝 전략 R3: 카드 60개 × 20분). 지원 제도는 해마다 바뀐다. 공공 API로 **"출처 원문이나 제도가 바뀌었는지"를 빌드할 때 자동으로 감지**하면 1인 운영의 가장 큰 위험(오래된 정보)이 줄어든다. 반면 응급실 병상, 문 연 병원, 약국처럼 **실시간 위치 데이터는 공식 서비스(E-GEN, 달빛어린이병원 목록)로 링크하는 편이 안전하다.** 정적 사이트가 들고 있는 복사본은 틀릴 수 있고, 새벽에 틀린 병원 정보는 곧 위험이 된다. 그리고 서버리스 함수, 위치 권한, 키 관리가 새로 필요해진다.

### 신청 불필요 / 링크로 대체

- **응급실 실시간 병상, 병·의원 찾기, 약국, 명절 비상진료**(국립중앙의료원) → E-GEN 앱·웹 링크. 실시간 데이터라 틀리면 위험하고, 서버리스 함수와 위치 정보가 필요하다.
- **달빛어린이병원** → `nmc.or.kr/nmc/babyList`·E-GEN MOONLIGHT 링크를 유지한다(전용 API는 찾지 못함).
- **심평원 병원정보서비스** → 소아청소년과 목록이 있어도 "지금 여는지"는 알 수 없다. 불필요.
- **식약처 e약은요(의약품개요정보)** → 제품명·용법이 핵심인 데이터라 "약 용량·제품명 금지" 규칙과 충돌한다. **부적합.**
- **어린이집 정보공개포털, 산후조리원(LOCALDATA), 산모·신생아 제공기관** → 시설 비교·선택 도구가 되면 커머스·비교에 가까워지고, 주제도 참고서 범위 밖이다. 공식 검색 링크로 충분하다.
- **에어코리아, 기상청 영향예보·생활기상지수** → 지역 선택 또는 위치 정보가 필요한 실시간 데이터다. 카드에서 "미세먼지·폭염·한파일 때" 기준을 설명하고 에어코리아·날씨누리 링크를 건다.
- **국가건강검진기관(건보공단)** → 영유아 검진 카드에서 건강iN 링크로 대체.

## 3. API별 상세

공통 사항 (data.go.kr 오픈 API):
- 신청: 공공데이터포털 회원가입 → 데이터 페이지에서 "활용신청" → 마이페이지에서 일반 인증키(Encoding/Decoding) 확인. 계정마다 키 하나를 여러 API에 쓴다.
- **CORS**: `apis.data.go.kr`는 `Access-Control-Allow-Origin` 헤더를 주지 않아 브라우저에서 직접 호출하면 막힌다는 개발자 기록이 있다(검색으로만 확인, velog·GitHub 사례). 그래서 **(b) 브라우저 직접 호출은 사실상 불가능**하다. 키도 노출된다. 아래에서는 (b)를 따로 적지 않는다.
- 이용허락범위: data.go.kr 오픈 API는 페이지마다 "이용허락범위" 칸이 있다. 이번에는 **하나도 원문으로 확인하지 못했다.** 신청할 때 확인한다.

### A. 병원·응급

#### A1. 국립중앙의료원 · 전국 응급의료기관 정보 조회 서비스
- 신청: https://www.data.go.kr/data/15000563/openapi.do · E-GEN 자체 신청 페이지: https://www.e-gen.or.kr/nemc/open_api.do?viewPage=application (data.go.kr 회원이어야 하고 인증키는 1인 1개)
- 데이터: 응급실 실시간 가용병상, 중증질환자 수용 가능 정보, 응급의료기관 목록·위치·기본정보, 외상센터, 응급실·중증질환 메시지
- 갱신: 병상은 실시간(응급실이 입력한 값)
- 키·한도: 개발·운영 모두 자동승인, 개발계정 1,000건. 운영계정은 활용사례를 등록하면 늘어난다(검색으로만 확인)
- 라이선스: 확인 필요
- BeInside 쓰임: 열 카드·119 카드의 "병원 갈 때" 칸. **그러나 쓰지 않는 것이 맞다.**
- 구현: (c)만 가능하다. 실시간이어서 빌드 시점 복사는 의미가 없고, 키를 숨겨야 한다.
- 개인정보·위치: 가까운 응급실을 보여 주려면 사용자 위치(Geolocation)나 주소 입력이 필요하다. 위치정보를 받아 서비스하면 「위치정보의 보호 및 이용 등에 관한 법률」상 위치기반서비스사업 신고 대상인지 따져야 한다(**확인 필요**, 법률 판단은 이 조사 범위 밖).
- 판단: **불필요, E-GEN 링크로 대체.** (1) 병상 수는 응급실이 입력한 값이라 실제 수용과 다를 수 있다. 새벽에 "병상 있음"을 보고 갔다가 받지 못하면 BeInside가 원인이 된다. (2) 공식 E-GEN 앱·웹, 네이버·카카오 지도가 같은 데이터를 이미 보여 준다. (3) 서버리스, 키 관리, 장애 대응은 1인 운영에 맞지 않는다. (4) 급할 때 정답은 "119에 전화"다. 이미 `js/cards.js`의 `er` 링크가 E-GEN으로 간다.

#### A2. 국립중앙의료원 · 전국 병·의원 찾기 서비스

## 4. 구현 방식별 묶음

### (a) 빌드할 때 받아 정적으로 넣기 — 추천 방식

| 용도 | API | 결과물 | 커밋 여부 |
|---|---|---|---|
| 출처 변경 감지 | G1 국가건강정보포털 | `data/public/source-hashes.json` (콘텐츠 번호, 수정일, 해시, 받은 날짜) | 해시만 커밋 |
| 제도 링크·변경 감지 | C1 중앙부처복지서비스, C3 공공서비스(혜택) | `data/public/benefits.json` (서비스ID, 이름, 공식 요약, 신청처, 문의처, 상세 URL, 수정일, 받은 날짜) | 커밋. 카드 렌더러가 읽는다 |
| 접종 일정 대조 | B1 예방접종 정보 | `data/public/vaccine.json` | 커밋(대조용) |
| 리콜·회수 점검 | E1 공산품 리콜, E3 식품 회수 | 콘솔 출력만 | 커밋 안 함 |
| (나중) 지역 연결 | H1 보건소, D2 육아종합지원센터, C2 지자체복지 | `data/public/local/*.json` | 커밋 |

운영 방식 제안(코드는 이번에 고치지 않는다):
- 새 스크립트 `scripts/fetch-public-data.mjs`(가칭)를 둔다. `build-cards.mjs`처럼 **의존성 없이** Node 내장 `fetch`로 쓴다. 키는 `process.env.DATA_GO_KR_KEY`, `process.env.KDCA_HEALTH_KEY`에서만 읽는다.
- `.gitignore`에 지금 `.env` 줄이 **없다.** 키 파일을 쓰기 전에 `.env`를 추가해야 한다(키 유출 방지).
- 순서: `npm run fetch:public` → 변경 경고 확인 → 카드 수정·확인 날짜 갱신 → `npm run build:cards` → `npm test` → 커밋. 월 1회 + 카드 작업할 때.
- 받은 데이터마다 **받은 날짜**를 함께 저장하고, 카드에 "공식 정보 기준일: YYYY-MM-DD"로 보여 준다(출처와 날짜 원칙).
- 응답이 비거나 오류이면 이전 파일을 그대로 두고 경고만 낸다. 빈 데이터로 덮어쓰지 않는다.
- 테스트 아이디어: `benefits.json`의 모든 URL이 공식 도메인(`gov.kr`, `bokjiro.go.kr` 등)인지, 문의 전화가 렌더링될 때 `tel:` 링크인지 검사한다.

### (b) 브라우저에서 직접 호출 — 쓰지 않는다

- `apis.data.go.kr`는 CORS 헤더를 주지 않는다(검색으로만 확인). 가능하더라도 인증키가 페이지 소스에 그대로 드러난다.
- 해당 후보: 없음.

### (c) Vercel 서버리스 함수가 필요함 — 지금은 만들지 않는다

- 해당 후보: A1 응급실 병상, A2 병·의원, A3 약국, A4 명절 비상진료, F1 에어코리아, F2 영향예보, F3 생활기상지수, G2 검진기관
- 공통 문제: 새 인프라(기능 동결 예외 필요), 키를 Vercel 환경변수로 관리, 장애 대응, 호출 한도, 대부분 **사용자 위치**가 필요하다. Vercel Hobby 요금제는 비상업 개인용이며 함수 호출 월 100만 회, 실행 시간 제한이 있다(검색으로만 확인, https://vercel.com/docs/plans/hobby).
- 무엇보다 **같은 일을 공식 서비스가 이미 더 정확하게 한다.** 새벽의 판단 흐름은 "위험 신호 → 119 / 그 밖에 밤이면 달빛어린이병원·응급실 → E-GEN에서 찾기"다. 링크 하나가 서버리스 함수보다 빠르고 틀릴 일이 적다.
